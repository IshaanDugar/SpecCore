How one round works

  1. The draft guesses ahead.

    The small model (0.66M parameters) proposes the next 2 tokens. It is cheap to run.

  2. The big model checks every guess in one pass.

    On SpecCore one read of the weights serves all the guesses together, so checking two costs far less than writing two.

  3. Agreed guesses are kept.

    At the first disagreement the big model’s own token is used instead, so the result is exactly what the big model would write alone.

    About these numbers
    
The models, tokens, guesses and probabilities are real. They come from the integer versions of both models, which use exactly the arithmetic of the SpecCore RTL; on every prompt simulated on the core it produced the same tokens. The core’s RTL itself is not running here: cycle-accurate simulation takes about 2 minutes per token.

    
Speed: each pass is charged the cycles measured for it on the core in simulation (Vivado xsim), with the attention part scaled with context length (an estimate). Time assumes the core’s 122.7 MHz clock. After every run the big model also writes the text alone, and the page checks the two are identical.

    
The models are small (5.2M and 0.66M parameters, trained on Python from scratch), so the code looks right in style but is often wrong and can repeat itself. Repeats are easy to guess, so they push the speedup up.
