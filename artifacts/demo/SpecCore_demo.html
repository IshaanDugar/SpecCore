A 5.2M-parameter code model generates text and a 0.66M-parameter draft guesses ahead. Left: plain decoding, one full read of the weights per token. Right: speculative decoding, where the LLM unit checks every guess in one pass over the weights and the output stays identical. Both run on the same cycle clock. The model is tiny, so its code is plausible rather than correct; what matters here is that both lanes write exactly the same text.

Where the numbers come from. The top panel and the “Same prompt on the FPGA” figures are measured on the KV260: the core runs in the FPGA fabric, the model weights sit in the board’s DDR4, and every output is checked bit for bit against a reference. On the board the core’s cycle counts are identical to the RTL simulation (a full 100,556,084-cycle model run matched exactly), and DDR waits add about 1% wall time. The replay animation is built from the integer model (the core’s exact arithmetic; its round counts match the board runs) and per-pass cycle costs measured on the core, so the replay clock is an estimate built from measured parts. Times in ms use the board’s 50 MHz clock.
